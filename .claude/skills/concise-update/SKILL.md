# Concise update

The owner wants answers that are **concise and complete**: everything that
matters, nothing that doesn't. Details belong in the repo docs, not in chat.

## Structure

Start with the answer or result. Then use only the sections that apply, in
this order:

1. **Key findings**
2. **Analysis:** what it means for the plan or the decision.
3. **Open points:** decisions needed, unverified items, risks.
4. **Next steps:** who does what.
5. **Files:** where the details live.

## Rules

- **Leave out:**
  - process narration (which agents ran, tool calls, commit messages);
  - restating context the owner already has;
  - repeated caveats;
  - long tables (link the file instead).
- **Keep:**
  - failures and errors;
  - anything not verified;
  - risks to money, tax or privacy.
- **Questions:** ask only when blocked, at the end.
