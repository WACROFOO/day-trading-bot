## The idea, in one paragraph

The computer watches a list of stocks the way Ross does: find the ones
gapping up before the open, throw out the ones that break his rules
(wrong price range, too many shares, no news), wait for the first
pullback, and only then consider an entry with a stop underneath. Every
one of those decisions is written into a diary at the moment it is made,
with exactly what was known at that moment. Later, the computer looks at
what the stock actually did and grades the decision. That grading — not
the profit — is the point of the exercise, because the earlier research
in this repo found this strategy lost money over 894 trading days.

## What is working now

| piece | plain meaning | proof |
|---|---|---|
| **The rule-checker** | throws out a stock the moment it breaks one of Ross's rules, and never lets a thrown-out stock get an entry plan | 37 tests |
| **The diary** | writes every decision down — taken, refused, or thrown out — with the price, the news, and the reason, at that instant | 18 tests; a repeat of the same morning adds nothing twice |
| **The trader program** | reads the diary and either refuses, logs, or places the order. Right now it is in **log-only mode**: it does everything except send the order | 11 tests |
| **The connection to your paper account** | confirmed live today: it can see the account, price an order, place a bracket (entry + stop together) and cancel it | you saw `PASS` on both scripts |
| **The safety lock** | the program refuses to run against anything that is not a paper account. There is no switch to turn this off, and a test fails if one is added | test |
| **The grader** | after the session, fills in what the stock did next for every decision — including the ones passed on | 10 tests |
| **The honesty check** | re-runs every recorded decision from the diary and confirms the same answer comes out. If the diary and the code ever disagree, this catches it | 5 of 5 on the practice run |
| **The comparison** | measures the strategy against two dumb alternatives on the same stocks at the same moments, so a good result cannot be luck of the names | built |
| **The one-command day** | `python3 scripts/day.py` runs the whole morning in order and writes the day's report | tested with a dry run |
| **The feed-health rule** | if the live price feed goes stale or delayed, every verdict becomes STALE and no plan is armed. This was missing until today — the screen once showed "1 day behind" and an armed entry in the same frame | 4 tests |
| **The alignment measurement** | a probe that checks whether the paper account sees the same prices as the live one, and a per-fill table showing the decision price, the fill, the price on screen at the fill, and the seconds between | 9 tests; probe **not yet run** |
| **The pre-market question** | a test that asks your broker whether a stop order actually works before 09:30. Both possible answers are already built for | script exists, **not yet run** — needs a weekday morning |
| **After-hours safety** | if a position is still open after 16:00 the program flags it and waits for you. It will not sell on its own | 7 tests |
| **The screen** | the bottom-right verdict box now shows the server's decision, not its own guess. A thrown-out stock reads "suppressed · KILLED" instead of "ARMED" | tested in a real browser |

Over 500 automated checks pass. Two known failures existed before today's
work and are written down in `BASELINE-2026-09-06.md` so nobody mistakes
them for new damage.

## What is not done

| item | why it matters | who does it |
|---|---|---|
| **Set your numbers** in `docs/preregistration.md` | how much to risk per trade, how many trades before judging, what counts as failure. Written before the first order, or the exercise proves nothing | you — "as proposed" is a valid answer |
| **Run the pre-market test** | decides whether pre-market entries get a real stop or a watched one. Nothing about pre-market trading is decidable until then | the day command does it Monday; you paste the output only if it says `inconclusive` |
| **Tell IBKR to give the paper account live prices** | IBKR judges paper fills against whatever prices the paper account can see. Today it sees none. In Client Portal › Settings › Paper Trading Account, turn on sharing of real-time market data with the paper account. The morning command measures whether it worked and blocks real orders until it has | you, once |
| **Five log-only sessions** | the diary has to prove itself honest on real data before any order is sent | the day command, five mornings |
| **One pre-existing screen bug** | the "LIVE / STALE" badge sometimes repaints wrongly. Cosmetic, not a trading risk, and not from today's work | me, later |
| **Real fills are still unproven** | the paper account simulates fills. The diary records the real screen price at each fill so we can judge whether the fill was believable, but that judgement has not happened yet | phase B onward |

## What you do

**Before 06:55 ET (12:55 France) on a weekday:** log in to TWS and to IB
Gateway on the paper account. Then:

```bash
cd ~/day-trading-bot && git pull origin claude/playbook-pullback-explanation-tg5c33
python3 scripts/day.py
```

Leave it. After 11:30 ET it writes the report and stops. Read it with:

```bash
python3 scripts/exercise.py report
```

If anything in that report reads `✗`, send it to me. If nothing does, the
day worked.

## What this cannot tell you, even when it all works

- Whether the strategy makes money. The prior evidence says it does not.
  This measures whether the *selection* is any good.
- Whether a paper fill would have happened in the real market.
- What happens during a trading halt. The corpus itself says this cannot
  be modelled; only the live diary will accumulate it.
- Anything about a different month. One window proves one window.

## Addendum — 7 September, after the first live run (a market holiday)

The whole chain ran on a live broker connection for the first time. The
market was closed (Labor Day), and every part that depends on a market
correctly said so. Four things were found and fixed the same day, with the
market still closed:

| found | fixed |
|---|---|
| the desk wrote its diary but **never saved it to disk**, so the trader program, a separate process, would have seen nothing on a real day. The tests never noticed because they read through the same connection | every write is now committed; a test drives the real desk with the fake broker and reads through a second connection, as the trader program does |
| the stop probe ran at 06:55 and refused itself (it needs 07:00) — it would have been skipped every day | it now runs at the first pass after 07:00 |
| nothing knew the market was closed | NYSE holidays are data; the command refuses to start and says why |
| the desk's float came from SEC shares outstanding (an upper bound) while the gap scan had the real float from finviz; the only survivor was armed on a 22M bound | the scan's floats are handed to the desk each morning |

**One open question the holiday could not answer.** IBKR refused the paper
session market data with error 10197, "competing live session": the live
TWS login holds the subscriptions. The runbook has the two tests for
Tuesday. If the paper account only sees prices when it is the sole login,
the exercise runs off the paper Gateway alone.
